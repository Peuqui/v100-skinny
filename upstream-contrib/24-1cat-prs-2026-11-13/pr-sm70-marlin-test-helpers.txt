[Test][SM70] Marlin test helpers pack through the loaders' repack ops

Problem: in an sm_70-only build (MARLIN_SM70_ARCHS and no other Marlin arch, so Volta and Turing both take the SM70 Marlin kernels; ops.sm70_marlin_available() is True on both) tests/kernels/quantization/test_marlin_gemm.py fails almost entirely without a computation error. On main (119cae740, the three files are unchanged up to d722fab7c) 561 of 593 cases fail on a Tesla V100 and on a Quadro RTX 8000 alike; tests/kernels/moe/test_moe.py -k marlin fails 232 of 261 cases on the V100 and 234 on the RTX. Two causes:
1. marlin_quantize and awq_marlin_quantize in vllm/model_executor/layers/quantization/utils/marlin_utils_test.py build the upstream Marlin weight layout in Python (marlin_weights). The SM70 repack ops gptq_marlin_repack and awq_marlin_repack, which the loaders call, write the SM70 kernels' own layout. With the Python packing the SM70 GEMM output has a relative error of 1.43 to 1.51 against the reference; with gptq_pack plus ops.gptq_marlin_repack it is 0.0 (uint4b8 and uint8b128, group size 128 and -1). The FP8 helper marlin_quant_fp8_torch already packs through ops.gptq_marlin_repack and is exact on SM70. test_gptq_marlin_repack and test_awq_marlin_repack compare the repack op with the Python layout, so they fail on this build by construction.
2. The case generator produces combinations the SM70 build rejects on purpose (it serves fp16 activations and outputs with full K, without act_order and atomic-add output): "SM70 build only supports float16 activations", "requires full-K non act-order inputs" (without act_order the generator only emits is_k_full=False), act_order. tests/kernels/moe/test_moe.py uses the same helpers and generator pattern for the Marlin MoE cases.

Change: tests only (marlin_utils_test.py is a test helper module).
- marlin_quantize and awq_marlin_quantize pack through ops.gptq_marlin_repack / ops.awq_marlin_repack, as the loaders do. On builds with the upstream kernels this gives the same tensor as before: test_gptq_marlin_repack and test_awq_marlin_repack still compare the op with marlin_weights there, and they stay unchanged.
- test_marlin_gemm.py: on the SM70 build the generator keeps fp16 activations and outputs with full K, without act_order and atomic add; without act_order it keeps is_k_full=True instead of False (is_k_full changes nothing then, one value suffices). The two repack-layout tests skip on the SM70 build with the reason; the GEMM cases check its repack.
- test_moe.py: the Marlin MoE generator leaves out the same combinations on the SM70 build, the non-gated NVFP4 test and the batched NVFP4 cases use fp16 there, and the batched int8-activation case skips (no int8 activations in the SM70 build).

Not a duplicate: none of the 84 open PRs touches marlin_utils_test.py, test_marlin_gemm.py or tests/kernels/moe/test_moe.py (checked on 2026-11-14). #1507 fixes the SM70 Marlin bias in the kernels; this PR changes only the tests. #1506 brings other SM70 test files in line and does not touch these three.

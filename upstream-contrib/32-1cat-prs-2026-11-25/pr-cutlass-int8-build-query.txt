[Bugfix][Kernel] CUTLASS INT8 linear: admit it only where the build has a kernel

Based on 1Cat main 73da3445d; one commit.

Problem: CutlassInt8ScaledMMLinearKernel.is_supported() ignores its compute_capability argument and returns True on every CUDA GPU. cutlass_scaled_mm has INT8 kernels only in the SM90 family (capabilities 90 to 99) and in the c2x family (from capability 75; it also serves higher capabilities when no newer family is compiled), and only when the build compiled them (ENABLE_SCALED_MM_SM90, ENABLE_SCALED_MM_C2X). The SM100 and SM120 dispatchers have no INT8 function (scaled_mm_c3x_sm100.cu and scaled_mm_c3x_sm120.cu pass nullptr). Where no kernel exists the selector still picks CUTLASS and the first GEMM fails, for example with "No compiled cutlass_scaled_mm for a compute capability less than CUDA device capability: 70" on a Volta GPU or with "Int8 not supported on SM..." on Blackwell, although the next entry of _POSSIBLE_INT8_KERNELS for CUDA, TritonInt8ScaledMMLinearKernel, accepts every CUDA device in its own is_supported().

Change:
- csrc/libtorch_stable/quantization/w8a8/cutlass/scaled_mm_entry.cu: new cutlass_scaled_mm_supports_int8(capability), declared in ops.h, registered in torch_bindings.cpp, with the Python wrapper ops.cutlass_scaled_mm_supports_int8 in vllm/_custom_ops.py. It mirrors the dispatch of cutlass_scaled_mm: the first compiled kernel family a call would take decides. A compiled SM120 or SM100 dispatcher answers False for its capabilities (it has no INT8 function), a compiled SM90 family answers True for capabilities 90 to 99, a compiled c2x family answers True from 75, otherwise False. cutlass_scaled_mm_azp dispatches differently from capability 100 up (it has no SM100 or SM120 branch and takes the SM90 family, else c2x); the query follows cutlass_scaled_mm, the symmetric path, and a comment in the code says so.
- vllm/model_executor/layers/quantization/utils/w8a8_utils.py: cutlass_int8_supported(capability) asks the query through the existing _cutlass_capability_probe, like cutlass_fp8_supported and cutlass_block_fp8_supported. A native library built before this change has no such op; the probe then answers False (it catches the AttributeError), so a stale library declines CUTLASS INT8 instead of raising, also on GPUs where that library has the kernels; the selector then moves on to the next INT8 kernel.
- vllm/model_executor/kernels/linear/scaled_mm/cutlass.py: CutlassInt8ScaledMMLinearKernel.is_supported() asks cutlass_int8_supported when a compute_capability is given and returns False with the reason "this build has no CUTLASS INT8 GEMM for compute capability N.", so the selector moves on to the next INT8 kernel with a stated reason. Without a compute_capability the answer is unchanged. FP8 selection is not touched.
- tests/quantization/test_compressed_tensors.py: the fixture cutlass_int8_gemm_build, which issued an INT8 GEMM on the device to find out whether the build has a kernel (its docstring noted that no INT8 build query existed), now asks cutlass_int8_supported for the device capability and skips when it answers False or no CUDA device is present.
- tests/kernels/quantization/test_scaled_mm_kernel_selection.py: three CPU tests: is_supported() follows the query when it answers yes and when it answers no, returns (True, None) without a capability, and declines when the query raises AttributeError, as torch does for an op missing from the library.
- tests/kernels/quantization/test_cutlass_scaled_mm.py: test_cutlass_int8_support_matches_dispatch performs an actual INT8 cutlass_scaled_mm call on the running GPU and asserts that the query and is_supported() give the answer the call gave, whichever kernels the build contains (it also accepts the "Int8 not supported" error of the SM100 and SM120 dispatchers as "no kernel"); test_cutlass_int8_support_opcheck runs opcheck on the new op.
- The new op exists only in a rebuilt _C_stable_libtorch; until then the probe declines CUTLASS INT8 as described above.

Evidence: there is no throughput claim; this is a selection fix. What was run, on our GPUs and a build without INT8 CUTLASS kernels (the existing INT8 tests of test_cutlass_scaled_mm.py fail there on main as well, see Tests): on the Tesla V100 (capability 70) and the Quadro RTX 8000 (capability 75) the INT8 call fails with "No compiled cutlass_scaled_mm ... capability: 70" and "... 75", and test_cutlass_int8_support_matches_dispatch passes on both: the query and is_supported() answer False, as the call does. Not run: a build with the SM90 or c2x INT8 kernels (the True side of the query is only checked by reading the code), a Blackwell GPU (the "Int8 not supported" branch of the new test), and the selector reaching TritonInt8ScaledMMLinearKernel (read from vllm/model_executor/kernels/linear/__init__.py and scaled_mm/triton.py, not executed).

On the remaining gap you mention (a tie group strictly above the row minimum that straddles k), one data point in case it helps later: 1Cat-vLLM, a vLLM fork for Volta and Turing GPUs, does not show it, without changing the pivot search. Its kernel flags every row in which the tie group at the k-th value would have to be cut (num_keep < num_duplicate_logit, plus rows whose final pivot is not below the row maximum) and recomputes only those rows with apply_top_k_top_p_pytorch on the host (1CatAI/1Cat-vLLM commit 7faa7f682). That costs a host sync, which your path avoids on purpose, so this is not a request to do the same.

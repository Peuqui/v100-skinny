----- Text -----

Problem: check_shared_mem() in vllm/model_executor/layers/fla/ops/utils.py read the maximum shared memory of index 0 of the visible devices. chunk_o.py (BKV_LIST) and cumsum.py (BS_LIST) evaluate it at import, so every worker of a mixed rig chose its chunk_o and cumsum tile lists from the first visible card. With an Ampere-class card first, a worker on a V100 (96 KiB of shared memory per block, 98,304 bytes) would be given tile lists that need the larger shared memory of the other card. The threshold of the default architecture is 102,400 bytes (100 KiB).

Change:
- check_shared_mem() takes tensor_idx=None. Without an explicit index it asks current_platform.resolve_device_id(None), the existing answer to "the device this process runs on": the device the worker selected once CUDA is initialized, index 0 of the visibility list before, and it never creates a CUDA context. An explicit tensor_idx still works.
- The first version of this fix called torch.cuda.current_device(). Because chunk_o.py and cumsum.py call check_shared_mem() at import, importing the FLA ops then created a CUDA context in every process, also in processes that must not hold one (API server, CPU helpers); tests/model_executor/test_fla_context_free_import.py fails on that. resolve_device_id avoids it.
- No change where all visible cards are on the same side of the 100 KiB threshold: a rig with a V100 (96 KiB) and a Quadro RTX 8000 (64 KiB) picks the same tile lists as before, because both are below it. The change matters when a card above the threshold is visible next to one below it.
- Limit: the result is cached and evaluated when the module is first imported. A process that imports the FLA ops before the worker has selected its device gets index 0, as before; the worker processes import them while loading the model.

Evidence:
- tests/kernels/test_fla_shared_mem_per_device.py (CPU, stubs get_all_max_shared_mem with [166912, 98304] and resolve_device_id): the worker on device 1 gets False, tensor_idx=0 still gives True.
- Probe with a Quadro RTX 8000 and a V100 visible: without a CUDA context index 0 and no CUDA initialization; after set_device(1) index 1 (the V100, 98,304 bytes of shared memory, the RTX 65,536).
- No kernel-speed claim: on our rig of V100 and Quadro RTX 8000 the tile lists do not change.

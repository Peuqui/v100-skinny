Problem: running every SM70/Volta/Turing test file of main on a Tesla V100 (489 files, one pytest process per file, 10 min per file), 73 of the first 75 test files this PR touches fail on main 119cae740; the 76th, tests/tools/test_flash_v100_build_architecture.py, runs without a GPU and fails on main cb97f379b (item 9); their code and tests are unchanged in 156cdaf1b. Almost all failures are tests that main's own changes left behind: native ops are now bound with the engine policy when weights are prepared, switches moved from VLLM_* environment reads into engine-owned policies, helpers moved (SM70 qualification to models.config, the QPN8 dispatch workspace to kernels/linear/qpn/fp8.py), and __init__ sets attributes that fakes built with __new__ lack. Four of the stale tests come from our own merged PRs (c6ae9c5d7, f2674c58c and the reduced draft vocabulary backport), which did not update tests that pin the changed code.

With these skips an RTX 8000 run of the file hung at test_compressed_tensors_mxfp8_moe_setup, which alone fails in 23 s. Cause: test_qwen3_coder_awq4_moe_postload_does_not_require_sm70_hidden_size runs the CPU MoE post-load in the pytest process and so starts GNU OpenMP threads there (torch 2.10 ships libgomp); the next EngineCore forked from that process hangs in its first parallel CPU op (faulthandler: the forked EngineCore waits in gpu_input_batch.py:164, a CPU torch.zeros, the parent in wait_for_engine_startup). On main the bfloat16 logprobs test loads an HF model to the GPU early in the file, so vLLM forces spawn for every later EngineCore ("CUDA is initialized") and the hang stays hidden: the DeprecationWarning of multiprocessing's fork appears 2 times on main and 15 times on this branch. create_new_process_for_each_test() now runs the post-load test in a process of its own. The post-load test followed by the MXFP8 test hangs until the timeout (7 min) without this; the whole file does not hang with OMP_NUM_THREADS=1, with VLLM_WORKER_MULTIPROC_METHOD=spawn, or with this change and the default fork and threads.
8. FP8 route snapshot: test_sm70_fp8_kernel_selection.py::test_legacy_dispatch_snapshot records {"error": "Explicit SM70 native policy requires the policy-argument ABI ..."} for every probed layer. The probe in tools/sm70_fp8_route_snapshot.py replaces torch.ops._C with doubles that have no policy-argument ABI; since 495fb442a ("Bind provider policy and native resources to engine lifecycle") NativeBindings refuses captured values without that ABI on purpose, where it used to drop them. git bisect between the snapshot's last update 333217c91 (passes) and main finds 495fb442a. The probe now binds plan-only native bindings (no policy arguments, operations resolved from vllm._sm70_ops, where it installs its recorders) in the FP8 provider and in sm70_layer_workspaces; the policy binding has its own tests in test_sm70_native_policy.py. The snapshot then equals the checked-in sm70_fp8_routes.json in all 324 cases and 226 edge cases, so the FP8 routes are unchanged since 333217c91. The --baseline-ref mode of tools/sm70_route_snapshot.py fails the same way with and without this change (the old fp8.py calls today's init_sm70_fp8_linear_kernel with is_bmm); not changed here.

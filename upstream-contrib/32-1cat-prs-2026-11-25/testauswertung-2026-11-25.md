## 1. Ergebnis

Von den roten Dateien ist **ein echter Fehler unserer Zweige** im Produktionscode, plus zwei Testfehler durch das Rebase auf main und drei CPU-Testdefekte:

1. **`vllm/v1/worker/gpu/prefill_overlap.py:107`** (Commit 4ec816be4, enthalten in pr-r-triton #1282, pr-stack #1347, pr-r-glm53 #1286, pr-r-glm53ph #1348): liest `input_batch.max_seq_len_np`, das 1Cat main seit dd8295bb9 (10.11.) nicht mehr hat. Jede TP-Prefill-Überlappung (`tp_prefill_overlap_min_tokens > 0`, z. B. das 27B auf TP2) stürzt in `token_range_batch` mit AttributeError ab. 2 Tests rot auf allen drei Geräten. Zeile streichen.
2. **`tests/kernels/test_deepseek_v4_sm70_indexer.py:366`** (pr-r-triton, pr-stack, pr-r-glm53, pr-r-glm53ph; V100 und RTX): Aufruf von `sm70_indexer_prefill_logits` ohne das Pflicht-Keyword `triton_tensor_cores` (Commit 6c0a85448); der Test kam erst am 10.11. über main dazu. Nur Test, Produktionscode in Ordnung.
3. **`tests/kernels/quantization/test_sm70_qpn8_block_fp8.py:425`** (alle Zweige mit Commit cc4751cf0: pr-r-turing, pr-r-triton, pr-stack, pr-r-glm53, pr-r-glm53ph; nur RTX): der vorbestehende Test verlangt `sm70_fp8_gated_silu` auch auf Turing, der Commit schaltet die Gated-Route dort bewusst ab. Test anpassen (16 Fälle).
4. CPU-Läufe: `test_skinny_sm70_moe.py` (12 Fälle, auf main grün, Commit 99d9f05c4 ruft `current_device_index()` in `is_supported_config`), `test_sm70_sparse.py` (2 Tests mit zu schwacher Skip-Bedingung), `test_vision_row_chunks.py` (3 ERROR, kein Skip ohne GPU). Alle auf v100/rtx grün, nur CPU-Lauf.
5. Rest ist **auf main selbst rot** oder Umgebung: veraltete Tests in 1Cat main (`test_sm70_fp8_prefill_exact_dense.py` ×2, `test_qwen4_exp_v2.py` ×1), CPU ohne GPU, und ein GPU-Build ohne CUTLASS-INT8-Kerne für SM70/SM75 (`test_cutlass_scaled_mm.py`).

Hinweis zur Umgebung der CPU-Läufe: `CUDA_VISIBLE_DEVICES=` lässt die NVML-Plattform trotzdem Karte 0 melden (geprüft: `NvmlCudaPlatform True DeviceCapability(7, 5)`), `current_platform.is_cuda()` ist also wahr und Skip-Bedingungen der Form `not is_cuda()` / `get_device_capability()[0] != 7` greifen nicht. Das erzeugt die „No CUDA GPUs are available“-Fehler und ist auf main genauso.

[Test][SM70] Bring 75 SM70 test files in line with current main

Problem: running every SM70/Volta/Turing test file of main on a Tesla V100 (489 files, one pytest process per file, 10 min per file), 73 of the 75 test files this PR touches fail on main 119cae740; their code and tests are unchanged in 156cdaf1b. Almost all failures are tests that main's own changes left behind: native ops are now bound with the engine policy when weights are prepared, switches moved from VLLM_* environment reads into engine-owned policies, helpers moved (SM70 qualification to models.config, the QPN8 dispatch workspace to kernels/linear/qpn/fp8.py), and __init__ sets attributes that fakes built with __new__ lack. A few are hardware limits that the tests did not skip. Four of the stale tests come from our own merged PRs (c6ae9c5d7, f2674c58c and the reduced draft vocabulary backport), which did not update tests that pin the changed code.

Compressed tensors: each test that needs a scheme skips when the scheme's get_min_capability does not admit the GPU (INT8 W8A8 from SM75, FP8 W8A8 from SM89, WNA16 by its own minimum); the INT8 logprobs comparison runs in bfloat16 and skips below SM80; test_compressed_tensors_fp8 checks the input scale only for W8A8, since weight-only W8A16 drops it. With these skips an RTX 8000 run of the file hung at test_compressed_tensors_mxfp8_moe_setup, which alone fails in 23 s. Cause: test_qwen3_coder_awq4_moe_postload_does_not_require_sm70_hidden_size runs the CPU MoE post-load in the pytest process and so starts GNU OpenMP threads there (torch 2.10 ships libgomp); the next EngineCore forked from that process hangs in its first parallel CPU op (faulthandler: the forked EngineCore waits in gpu_input_batch.py:164, a CPU torch.zeros, the parent in wait_for_engine_startup). On main the bfloat16 logprobs test loads an HF model to the GPU early in the file, so vLLM forces spawn for every later EngineCore ("CUDA is initialized") and the hang stays hidden: the DeprecationWarning of multiprocessing's fork appears 2 times on main and 15 times on this branch. create_new_process_for_each_test() now runs the post-load test in a process of its own. The post-load test followed by the MXFP8 test hangs until the timeout (7 min) without this; the whole file does not hang with OMP_NUM_THREADS=1, with VLLM_WORKER_MULTIPROC_METHOD=spawn, or with this change and the default fork and threads.

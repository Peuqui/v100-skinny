## Ersetzte Abschnitte des PR-Textes

Neuer Titel:

[Feature][Qwen4Exp] PLE overflow cascade: device, pinned host, disk

"Purpose", Stufenliste ersetzen durch:

This PR adds an overflow cascade. Each rank fills three tiers, fastest first:

1. device memory of the compute card, up to its measured budget (the same
   computation as the existing auto placement: utilization budget minus
   allocated memory, the KV cache for `max_model_len` and a reserve),
2. a pinned host share,
3. the checkpoint on disk, mapped and read in place by the PLE offload worker;
   nothing is copied.

"Purpose", Nutzenliste ersetzen durch:

- Host memory back. On the rig below (PP4), available memory after startup is
  17.8 GiB with no host share and 13.6 GiB with 3 GiB, against about 2.7 GiB
  with the 12 GiB split this PR replaces.
- Identical output: greedy text is identical to the pre-change path.
- A small price, paid in prefill on a cold page cache: see the table below.
  Decode does not change measurably.
- Rows are never dropped: a table that does not fit the configured tiers fails
  at startup with a message that names the knobs.
- A fitting table pins nothing. With the cascade on, the host share is used
  only for what the device cannot hold.

An earlier version of this PR also had a store tier on a spare GPU. Measured
against the disk tier it saved 0.3 to 2.5 s of prefill on a cold cache and no
decode time, so it is gone; the configuration and the worker are simpler.

"Configuration" ersetzen durch:

| Variable | Meaning |
|---|---|
| `VLLM_QWEN4EXP_PLE_DISK=1` | Starts the cascade: rows beyond device and host are read from the checkpoint. |
| `VLLM_QWEN4EXP_PLE_HOST_GIB` | Unchanged meaning: pinned host share per rank. 0 skips the host tier. |

Example, PP4, the first stage holds what fits, the rest is read from disk:

```
VLLM_QWEN4EXP_PLE_HOST_GIB=0 VLLM_QWEN4EXP_PLE_DISK=1 vllm serve ... --pipeline-parallel-size 4
```

"How it works" — Punkte „Placement", „Registration", „Worker" ersetzen durch:

- Placement (`common/ple.py`): `plan_ple_placement` returns a three-tier
  `PLEPlacement` (device, host, disk rows). With the cascade, device rows come
  first up to the measured budget, then host, then disk. Without it the host
  share comes first and the device holds the rest, as before.
- Registration: each rank sends a `PLERemotePlacement` (vocabulary range,
  resident rows) in `PleOffloadRegistration.remote_placements`.
- Worker: the ranks' disk segments are disjoint in the global id space, so one
  output buffer serves every rank and each rank takes only its own slots. The
  disk tier reuses the disk lane's mmap reader, factored out as
  `_gather_mapped_rows` and used by both.
- The worker unmaps the checkpoint pages it read after each gather
  (`madvise(MADV_DONTNEED)` on the private, file-backed shard mappings; the
  pages stay in the page cache). Mapped pages are ones the kernel keeps:
  without this the worker's mapped pages grew by ~150 MiB per request while
  the kernel swapped other processes out. Only shards the loader recorded as
  file-backed are released; on anonymous memory `MADV_DONTNEED` discards data.
  The existing test `test_ngram_embedding_retains_and_gathers_disk_shards`
  stubbed that check with anonymous tensors and now loads a real safetensors
  file.
- `copy_ple_embedding_shard_` copies with `copy_` directly instead of
  `source.to(...)` first: the caching allocator kept the staging block
  (382 MiB for one 0.37 GiB shard, measured in isolation) on the card that
  holds the device tier.

"Test Result", End-to-End-Abschnitt ersetzen durch:

262144`. Stage 0 holds 18.9 GiB of the 47.7 GiB table in device memory.

Major faults per request 36,000–118,000 (140–460 MiB read from the SSD).

## Kommentar für den PR (nach dem Push)

Updated and simplified: the store tier is gone. Measured against the disk tier
it saved little prefill on a cold cache and no decode time. Two memory fixes
came out of the measurements: the worker no longer keeps the checkpoint pages
it read mapped, and shards are copied to the device without a staging copy.
The description has the new configuration and PP4 numbers with real text on a
cold page cache.

Triton 3.6.0 plus the 26 commits of branch sm7x-tensor-cores, at commit 2adbae8bc2. Stock Triton lowers tl.dot to FMA on every NVIDIA GPU before sm_80; this build lowers it to tensor-core MMA on Volta (sm_70, mma.m8n8k4) and on Turing (sm_75, mma.m16n8k8), batched (3D) dots included. On both it double-buffers dot operands through registers into shared memory, since these GPUs have no cp.async, and on Turing it software-pipelines loops through registers. The changes are in the TritonGPU dialect and the NVIDIA backend; on other architectures the build compiles like Triton 3.6.0. Shown upstream in https://github.com/triton-lang/triton/discussions/12517.

Performance, measured with this wheel: fp16 GEMM, the same Triton matmul kernel under stock Triton 3.6.0 and under this build, best of a small tile sweep per shape, timed in CUDA graphs. To check that tl.dot reaches the tensor cores, save the following as mma_check.py and run python mma_check.py. It prints the GPU name, then True on sm_70 and sm_75 with this build (False with stock Triton 3.6.0), then True if the result matches torch.

import torch
import triton
import triton.language as tl


def dot16(a_ptr, b_ptr, c_ptr):
    offs = tl.arange(0, 16)
    tile = offs[:, None] * 16 + offs[None, :]
    tl.store(c_ptr + tile, tl.dot(tl.load(a_ptr + tile), tl.load(b_ptr + tile)))


dot16 = triton.jit(dot16)
a = torch.randn(16, 16, device="cuda", dtype=torch.float16)
c = torch.empty(16, 16, device="cuda", dtype=torch.float32)
ptx = dot16[(1,)](a, a, c).asm["ptx"]
print(torch.cuda.get_device_name(), "mma.sync" in ptx, torch.allclose(c, a.float() @ a.float(), atol=1e-2))
